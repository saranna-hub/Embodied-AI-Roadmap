> 核心区分：π₀.₆ 是基座策略谱系，π*₀.₆ 是经过 RECAP 经验学习的版本，星号不是 Transformer 架构符号。主要来源：[RECAP 论文](https://arxiv.org/abs/2511.14759) 与 [Physical Intelligence 研究主页](https://www.pi.website/blog)。

## 1. 行为克隆为什么不能自动变成最优机器人？

在动作监督数据中，模型拟合条件分布 $p_\theta(A\mid o,\ell)$。但示范包含多种质量：速度不同、是否抖动、碰撞次数、是否最后由人类纠正。单纯最大似然不会自动区分“都完成了但一种明显更好”。

同一个状态下，不同动作可能导致不同未来回报，因此要从执行经验引入质量区分，而不是把所有回放以相同权重作为真值。

## 2. 从策略梯度到优势条件化

常用优势函数为：

$$
A^\pi(s,a)=Q^\pi(s,a)-V^\pi(s).
$$

它衡量：当前动作相对该状态平均策略表现更好还是更差。假设可获得近似优势信号 $\hat A$，一个用于理解的加权监督式是：

$$
\mathcal L_{weighted}=\mathbb E\left[w(\hat A)\mathcal L_{FM}(o,A)\right],\quad w(\hat A)\ge 0.
$$

比如高质量动作增大权重。但**这不是宣称 RECAP 官方采用了上述具体加权 MSE 实现**：论文中的训练条件、回报定义、优势估计与筛选流程必须单独比对。这个抽象只是帮助理解“有区别地模仿”。

### 2.1 成功标签为什么不够？

某次装配成功可能用了很久且中途五次危险接触；另一次也成功但短、稳、无碰撞。把成功当单一二元 $r\in\{0,1\}$ 无法区分。应同时记录成功、耗时、轨迹长度、动作抖动、干预次数、潜在安全事故；再明确定义用哪个指标监督模型。

## 3. 什么是正确的数据闭环？

```text
     基础策略 π0.6
          ↓
 真机部署采集 observation, state, action, timestamps
          ↓
 结果质量打分 / 失败事件 / 人工纠正
          ↓
 数据校验：时间戳、动作坐标、来源、策略版本
          ↓
   区分示范、策略自主执行、人工纠正片段
          ↓
 建立监督与样本权重 / 质量条件 / 对比信号
          ↓
 受控训练 → 离线验证 → 受限线上评估
          └─────────────── 迭代
```

**误区**：如果机器人失败后由操作者接管，而你把修正动作误当成失败策略自己生成的，模型会把状态与动作来源关系学错。必须独立保存 `actor_source`、`intervention_start/end`、`policy_version`。

## 4. 一条训练样本至少保存什么？

| 字段 | 示例或类型 | 为什么重要 |
| --- | --- | --- |
| `episode_id` | 唯一轨迹编号 | 配对质量标签 |
| `robot_id / policy_id` | 设备和策略版本 | 避免不同分布混淆 |
| `timestamps` | 单调采样时间 | 视频-控制对齐 |
| `observations` | RGB/状态/语言 | 重放策略输入 |
| `actions` | 坐标、单位、命令类型 | 区分关节和末端动作 |
| `actor_source` | agent/teleop/correction | 避免人为动作混标 |
| `outcome` | success/fail/partial | 用作回报监督 |
| `quality_metrics` | 时间、接触、安全 | 不止二元成功 |
| `initial_condition` | 物体布局与治具 | 可比对的实验分层 |

## 5. 如何做出有说服力的消融？

固定网络与总数据量，仅改变经验学习方式：

| 实验 | 是否用失败 | 是否用纠正 | 是否用质量 |
| --- | --- | --- | --- |
| BC baseline | 否 | 否 | 否 |
| success-only | 否 | 是 | 否 |
| mixed BC | 是（等权） | 是 | 否 |
| quality-aware | 是（区分质量） | 是 | 是 |

额外设置「无真机迭代」「不同任务」「不同采集员」三组分布外测试。报告成功率置信区间、吞吐、每小时干预、单位任务数据成本。若 reward 使用人工评分，测试标注员一致性。

## 6. 训练实现必须处理的陷阱

- **反馈延迟**：成功往往发生在动作数秒后，当前 chunk 的影响无法直接归因。
- **分布外动作**：部署策略生成的失败动作可能离训练示范很远，盲目加权会不稳定。
- **经验偏差**：较新的策略数据可能本来就更高质量，若不控制策略版本，误将时间趋势当算法增益。
- **奖励作弊**：只优化速度可能导致危险动作，因此安全应该是硬约束或独立指标。
- **数据泄漏**：同一物体布局的纠正轨迹不能同时出现在训练和测试。

## 7. 对 EGO/UMI 数据管线有什么借鉴？

UMI/第一人称数据可以构造阶段完成度、人工纠正和质量标签，但无本体动作映射还需要几何标定、手物配准与执行约束。建议先做「轨迹质量评价与训练选择」再做完整 RL。第一步可以测对同一任务加入质量标注后成功率是否稳定提升，避免起步就承诺复现 π*₀.₆ 全量性能。

**复现边界**：可复现思想及替代性实验，不等于已获得作者私有的训练权重、全部机器人部署数据和原始实验环境。
