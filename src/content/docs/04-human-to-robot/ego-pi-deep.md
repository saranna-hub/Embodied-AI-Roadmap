# Ego-Pi：跨本体的语义迁移与动作对齐

[原论文](https://arxiv.org/abs/2606.08107) · [官方项目与演示](https://egopipaper.github.io/) · [π₀.₅ 基础](../../01-foundations/vla/pi05-deep/)

## 1. 到底转移了什么？

论文的任务是：机器人已经学过抓取、开盒、放置等基础技能；人类数据才有「按颜色分拣」「先开盒再放物体」「包装时先放盒后放熊」等新规则。核心验证是**高层任务规则与已有技能组合**迁移，并非证明任意人类视频能给机器人直接教会全新的低层灵巧接触技能。

官网展示：番茄分拣 co-train 37/40、robot-only 16/40；包装 9/10 对 1/10；开盒+装入 14/15 对 4/15。样本量较小，应该查看视频和论文评测协议，不能将其当成跨工厂普适成功率。

## 2. 为什么 π₀.₅ 不能直接输出五指双手？

π₀.₅ 常用动作容器上限 `D=32`；论文所用 Tesollo 灵巧手**每手 29 维**：平移 3 + 姿态旋转 6 + 手指 20；双手共 58 维。直接换成 58D 投影会改预训练参数，作者使用**左右手交错 Action Token**：

```text
物理时间 0: [左手29D] [右手29D]
物理时间 1: [左手29D] [右手29D]
...
一个动作token容器 = 32D，填充无效维度
50 个 token / 2 = 25 个双手物理动作步
```

把动作写为：

$$
A_{b,t,h,:}\in\mathbb R^{29},\quad h\in\{L,R\}
$$

构造 token index $k=2t+\mathbf1[h=R]$；每个 token 的前 29 维填动作，其余 3 维 padding：

$$
Z_{b,k,0:29}=A_{b,t,h,:},\quad Z_{b,k,29:32}=0.
$$

**这是假定固定左-右交错、用于读懂论文的编码表示**；实际必须复核源码是否对 padding loss mask 做了相同处理。注意 25 是双手时间步数，不是机器人只有 25 个控制周期的强制配置。

## 3. 人体与机器人对齐的两重矛盾

**视觉差异**：human 是人手，robot 是机械灵巧手；外观、遮挡、视角与骨架都不同。论文采用具深度关系的手指彩色骨架叠加，引入跨本体的可比较结构线索。颜色编码对应手指身份，遮挡时按深度正确显示远近关系。它不等于生成机械手视频，也不自动消除场景域差异。

**动作差异**：human 的关节角不能逐维当作机器人关节角。需建立手指对应、尺度/零位映射、工作空间约束；论文的目标是使两种 embodiment 的可用动作表征更一致。不同手型、手套/无手套、跟踪噪声都会改变映射质量。

一种可理解的标定目标（**工程化抽象，非论文原式**）：

$$
\min_{s,b}\sum_{t,j}\|\mathrm{FK}_{robot}(s_jq^h_{tj}+b_j)-p^h_{tj}\|^2
+\lambda\mathcal L_{limits}.
$$

它解释为何仅按角度数值匹配会失败：真正希望的是各手指在工作空间中完成相近动作，同时遵守机器人关节极限。

## 4. π₀.₅ Flow Matching 如何训练？

观测含相机图、状态与任务文本。对训练动作 chunk $A$ 和标准噪声 $\epsilon$ 构造：

$$
x_\tau=\tau A+(1-\tau)\epsilon,\quad
v^*=A-\epsilon.
$$

策略输出 $v_\theta(x_\tau,\tau,o,\ell)$；训练最小化速度场误差：

$$
\mathcal L=\mathbb E_{\tau,A,\epsilon}\|v_\theta-v^*\|^2.
$$

论文官网说明按照 human:robot **50:50** 混合批次，也训练子任务预测（但并非每项任务都必须依赖它）。推理时绝不能输入真值动作；从随机噪声迭代积分得到双手动作序列，拆成左右手 29D，再做反归一化、IK 与安全限制。

## 5. 开始实验之前的四个检查点

1. 读 [openpi 官方仓库](https://github.com/Physical-Intelligence/openpi) 的 `pi0.py`、`config.py`，确认 checkpoint 的 `action_dim` 与 `action_horizon`；**不要未经检测直接覆盖现有动作头**。
2. 将你的 EGO 手追踪与机器人本体建立对应，至少检查旋转单位、相机位姿与末端在同一坐标系下的误差。
3. 制作只在 human 中出现的新规则，而 robot 数据仍包含底层拿放技能。
4. 离线动作编码/解码循环必须能够还原左右手，padding 维不得成为有效控制指令。


## 训练闭环必备的数据契约（教学复现，不冒充论文官方代码）

| 字段 | 建议形状/含义 | 必须检查 |
|---|---|---|
| `video` | `[T,H,W,3]`，RGB，时间戳 | 摄像机内参、fps、曝光与同步 |
| `hand_pose` | `[T,2,4,4]`（若双手 6DoF） | 坐标系、跟踪置信度、缺失帧 |
| `fingers` | `[T,D_h]` | 人手模型/机器人手维度不同 |
| `robot_action` | `[T,D_r]` | 控制语义、单位、位置/增量 |
| `task_text` | 指令/阶段标签 | 不能从测试轨迹泄漏答案 |
| `provenance` | human/robot/synthetic | 每个样本都必须保存来源 |

**离线到在线最小验收顺序**：先确认样本格式与时间同步，再看单条轨迹投影和仿真回放，然后训练小数据过拟合，最后对同一机器人在真实闭环中测成功率。离线 loss 降低不等于完成真实世界机器人验证。

## 正确的对照实验

- A：只用机器人示范，建立现有能力基线。
- B：机器人+人类数据，固定机器人示范数量和训练预算。
- C：控制视觉一致性/动作对齐方式，单变量消融。
- D：明确留出「只在human中出现、robot从未示范的组合任务」作为测试场景。

报告任务成功率、至少多次随机重复、任务完成时长、干预/碰撞、推理延时，并保存评测初始条件。不能把论文实验结果当作自己的复现成绩。


## 6. 复现局限

原论文任务偏短程、固定摄像机、以放置类技能为主；并没有证明任意第一视角视频都可以无标注直接训练全新五指精细技能。论文中 human 视频甚至未要求 wrist camera，因此自有 EGO 设备并非需要完全复制其传感器布置。完整真实复现仍需检查作者是否发布完整训练数据/配置与模型权重。
