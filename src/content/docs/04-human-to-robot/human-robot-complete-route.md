# 人类第一视角 → 机器人 VLA：从视频到闭环执行

> **阅读顺序**：先读这篇总纲，再读 [迁移涌现](./human-robot-emergence-deep/) → [Ego-Pi](./ego-pi-deep/) → [EgoEngine](./egoengine-deep/)。三篇研究问题相互关联但并非同一个实现，也不能将其所有方法拼起来就宣称完成了作者的复现。

## 先搞清三种技术路线

| 路线 | 关键问题 | 人类数据的作用 | 需要什么基础 |
| --- | --- | --- | --- |
| Emergence of Human-to-Robot Transfer | 何时可以直接学到跨本体泛化？ | 引入训练中缺少的任务组合 | 多任务多本体机器人预训练 |
| Ego-Pi | 人与灵巧手机器人动作维度不同，怎么联合微调 π₀.₅？ | 教会机器人新的语义规则和技能顺序 | 已掌握基础抓取技能的机器人 VLA |
| EgoEngine | 人类视频没有机器人动作，怎么生成可执行示范？ | 变成对齐的视频+机器人动作训练对 | 几何重建、数字孪生、动作优化与视觉转换 |

## 统一工程流水线

```text
EGO/UMI/Aria 采集：RGB + IMU + 标定 + 时间戳
                      │
        [图像矫正/SLAM/手部姿态/任务标注/质量检查]
                      │
        ┌─────────────┴──────────────────┐
        │ 路线一：跨本体共同训练           │ 路线二：数据生成
        │ human 手轨迹 + robot 轨迹        │ 数字孪生与交互重建
        │ 动作统一/标签提示                │ 人体→机器人重定向+视觉转换
        └─────────────┬──────────────────┘
                      ↓
      统一数据 schema + provenance + train/val/test
                      ↓
             openpi π₀.₅ / 替代 VLA
                      ↓
     预训练初始化 → 数据混合 → FM损失 → checkpoint
                      ↓
       离线动作误差 → 仿真回放 → 安全真机闭环
                      ↓
        失败/纠正回采 → 重新质检 → 下次训练
```

这里的单一流水线是**将三篇方法归纳后的可落地研发建议**；不是任何一篇论文直接发表的整套一键脚本。

## 为什么要先用真机机器人示范打底？

机器人策略需要知道动作与机器人执行结果的对应关系；纯人类视频没有机器人的手指关节命令，也不能保证机械结构、抓取力或碰撞约束可行。Ego-Pi/迁移涌现路线通过机器人数据获得动作落地能力，再由 human 数据补上新规则；EgoEngine 则尝试显式生成可执行机器人动作和视觉观测，减少目标任务上的真实机器人演示依赖。

**不要混淆三个“零机器人数据”定义：**
1. 目标新任务没有 robot demo，但底座经历过机器人预训练。
2. 目标新任务只有 synthetic robot demo，仍有机器人运动学/仿真和可能的先验。
3. 从零训练并完全没有任何机器人数据。前三篇都不能被简单解释为第三种。

## 训练数学核心

对于 human 与 robot 域分别记作 $d\in\{h,r\}$，共同训练可以写成教学性的混合期望：

$$
\mathcal L_{mix}=\alpha\,\mathbb E_{D_h}[\mathcal L_{FM}]+(1-\alpha)\,\mathbb E_{D_r}[\mathcal L_{FM}].
$$

在 Ego-Pi 的公开配方中 human:robot batch 比例为 50:50；但其他论文未必采用同样比例。动作先做域相关的投影/重定向，再进入统一表征：不能直接将不同物理含义的向量硬拼接。

对连续动作 $A$，引入噪声 $\epsilon$、流时间 $\tau$：

$$
x_\tau=(1-\tau)\epsilon+\tau A,\quad
\mathcal L_{FM}=\mathbb E\|v_\theta(x_\tau,\tau,o,\ell)-(A-\epsilon)\|_2^2.
$$

**符号提醒**：此处 $`\tau=0`$ 是噪声端，$`\tau=1`$ 是数据端；openpi 不同讲义采用的时间方向可能相反，核源码时必须统一约定。训练时真值可见、推理时真值不可见。


## 训练闭环必备的数据契约（教学复现，不冒充论文官方代码）

| 字段 | 建议形状/含义 | 必须检查 |
|---|---|---|
| `video` | `[T,H,W,3]`，RGB，时间戳 | 摄像机内参、fps、曝光与同步 |
| `hand_pose` | `[T,2,4,4]`（若双手 6DoF） | 坐标系、跟踪置信度、缺失帧 |
| `fingers` | `[T,D_h]` | 人手模型/机器人手维度不同 |
| `robot_action` | `[T,D_r]` | 控制语义、单位、位置/增量 |
| `task_text` | 指令/阶段标签 | 不能从测试轨迹泄漏答案 |
| `provenance` | human/robot/synthetic | 每个样本都必须保存来源 |

**离线到在线最小验收顺序**：先确认样本格式与时间同步，再看单条轨迹投影和仿真回放，然后训练小数据过拟合，最后对同一机器人在真实闭环中测成功率。离线 loss 降低不等于完成真实世界机器人验证。

## 正确的对照实验

- A：只用机器人示范，建立现有能力基线。
- B：机器人+人类数据，固定机器人示范数量和训练预算。
- C：控制视觉一致性/动作对齐方式，单变量消融。
- D：明确留出「只在human中出现、robot从未示范的组合任务」作为测试场景。

报告任务成功率、至少多次随机重复、任务完成时长、干预/碰撞、推理延时，并保存评测初始条件。不能把论文实验结果当作自己的复现成绩。


## 四周可操作 Demo（这是建议配置，不是论文原实验）

**第 1 周｜采集+标签**：固定桌面、单相机或者头戴鱼眼校正，录制 30~100 段人类任务片段和少量机器人基本抓放数据；统一相机时钟，人工检查 10 段。输出 `episodes.jsonl`、图像、标定文件和可视化回放。

**第 2 周｜动作对齐**：使用固定 AprilTag/棋盘建立桌面世界坐标，求手腕位置，映射到机器人 EE 平移和旋转，夹爪先用简单开合代理；在 MuJoCo 回放，记录不可达、碰撞与追踪失效。输出可执行轨迹与失败报告。

**第 3 周｜训练**：从官方可下载 openpi checkpoint 出发，先在机器人示范上确认数据 schema 和训练脚本可运行，再试 B：混入 human 语义任务片段；固定训练 budget/robot demos。每晚保存训练曲线与动作可视化。资源不足时只做 LoRA 或较小网络的研究性替代，不称已复现原论文。

**第 4 周｜闭环与消融**：用「按颜色分拣两种零件」或「先开盒再放入零件」测试人类数据独有的规则；在线执行需设置限速、碰撞和急停。比较 Robot Only / Co-train / Retargeted Synthetic 三组，不仅比较 loss，也看成功率与失败类型。

## 与工业 EGO/UMI 采集平台对接

- 双目鱼眼 + IMU → 相机内参外参、时间对齐、VIO/SLAM 参考轨迹；固定桌面 AprilTag 能提供可重复的世界坐标。
- UMI 腕部相机和夹爪状态 → 可补足抓握事件、手物相对运动；但不能直接冒充五指关节角。
- 数据管线 → 每段保存 origin、calibration_version、action_space、机器人与人手标识、valid_mask、质量评级。
- 工厂验证优先「低速、无尖锐工具、可重复复位」任务，先仿真后实机。
