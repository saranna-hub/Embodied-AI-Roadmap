# Emergence of Human to Robot Transfer in Vision-Language-Action Models

[RSS 2026 论文](https://roboticsproceedings.org/rss22/p072.html) · [Physical Intelligence 官方解读](https://www.pi.website/research/human_to_robot) · [arXiv](https://arxiv.org/abs/2512.22414)

## 1. 一个反直觉结论

只把 human 视频加入小机器人模型，可能没有帮助；但如果基础 VLA 已经见过足够**多场景、多任务、多机器人本体**，同样的人类视频能显著改善只在人类示范中出现的任务情况。作者称之为跨本体迁移的涌现。**涌现不是不需要动作标注**；作者的 human 数据带 3D 人手位置形式的动作监督。

## 2. 什么保持不变，什么随实验改变？

官网明确：预训练机器人数据的数量与多样性变化；下游 human 微调数据保持不变，并且与最相关机器人数据混合共同微调。比如机器人数据只覆盖把鸡蛋放入盒子，human 示范的是按颜色将鸡蛋分类到不同盒子。

```text
Robot pretrain: zero → limited → diverse robot/tasks/embodiments
                                  │
               同一份 human 任务数据
                                  +
               同一份相关 robot 微调数据
                                  ↓
                         co-finetune π0.5
                                  ↓
                   Human-only 规则的机器人评测
```

只有固定 human 的数量、目标任务与评测环境，才可能把迁移改进归因于底座跨本体表征能力，而不是更多见过目标任务。

## 3. 怎么把 human 动作输入共同训练？

作者采用简单配方，把 human 当成一种新的 embodiment；动作由 **3D hand positions** 表示，而不是必须把人手重定向成机器人所有关节角。训练时共享模型主干，同时利用 embodiment / action 表示差异。

可写成教学抽象：

$$
\mathcal L=\lambda_h\mathbb E_{(o,a)\sim D_h}[\mathcal L_{FM}]
+\lambda_r\mathbb E_{(o,a)\sim D_r}[\mathcal L_{FM}].
$$

这里不是论文精确 loss 权重；重点是 human 与 robot 都有对动作形式的监督，且训练目标是在同一多本体基础模型上习得可跨域泛化的条件表示。无手位置数据的纯 RGB 视频并不能直接套此配方。

## 4. 表征是怎样“对齐”的？

作者从 VLM backbone 最后一层取 token 做平均池化，得到每条样本的 latent embedding，再用 t-SNE 展示 human/robot 分布。当预训练不足时，不同 embodiment 的嵌入彼此分离；增加训练多样性后，分布更重叠，跨域任务性能也同步提高。

不要将 t-SNE 两簇重叠等同于“证明完全学到相同语义”。更严谨的分析要控制采样量与随机种子，还可以在同任务不同本体下训练线性 probe，测任务类别准确率、domain classifier 准确率和表征相似度。

## 5. 为什么不是简单的参数量越大越好？

论文研究重点在**数据覆盖的多样性**，不是仅报告参数数量越大性能越好。预训练需要包含更多对象、操作方式、场景和机器人形态，使视觉语义、操作目标和动作之间建立可复用的共同结构。对自身项目而言，如果底座仅在六个高度相似工位训练，堆叠 100 倍 human 录像未必产生论文的迁移效果。

## 6. 真正可证伪的实验矩阵

| 预训练 | 微调 | 新任务机器人验证 | 预期判断 |
| --- | --- | --- | --- |
| 小规模 robot | robot only | 基线 | 当前已学的技能 |
| 小规模 robot | robot+human | 比较 | 是否有跨域收益 |
| 多样 robot | robot only | 基线 | 多样机器人预训练自身收益 |
| 多样 robot | robot+human | 比较 | human 的额外贡献 |

统一机器人示范数量、human 数量、训练步数、数据划分，并固定评测随机种子；对训练未见场景按任务结构分别报告成功率。若多样底座收益来自更多训练数据而不只是多样性，还需做等规模但低多样性的控制组。


## 训练闭环必备的数据契约（教学复现，不冒充论文官方代码）

| 字段 | 建议形状/含义 | 必须检查 |
|---|---|---|
| `video` | `[T,H,W,3]`，RGB，时间戳 | 摄像机内参、fps、曝光与同步 |
| `hand_pose` | `[T,2,4,4]`（若双手 6DoF） | 坐标系、跟踪置信度、缺失帧 |
| `fingers` | `[T,D_h]` | 人手模型/机器人手维度不同 |
| `robot_action` | `[T,D_r]` | 控制语义、单位、位置/增量 |
| `task_text` | 指令/阶段标签 | 不能从测试轨迹泄漏答案 |
| `provenance` | human/robot/synthetic | 每个样本都必须保存来源 |

**离线到在线最小验收顺序**：先确认样本格式与时间同步，再看单条轨迹投影和仿真回放，然后训练小数据过拟合，最后对同一机器人在真实闭环中测成功率。离线 loss 降低不等于完成真实世界机器人验证。

## 正确的对照实验

- A：只用机器人示范，建立现有能力基线。
- B：机器人+人类数据，固定机器人示范数量和训练预算。
- C：控制视觉一致性/动作对齐方式，单变量消融。
- D：明确留出「只在human中出现、robot从未示范的组合任务」作为测试场景。

报告任务成功率、至少多次随机重复、任务完成时长、干预/碰撞、推理延时，并保存评测初始条件。不能把论文实验结果当作自己的复现成绩。


## 7. EGO/UMI 管线如何利用这篇？

可以先将 RGB 视频 + 世界系手腕轨迹 + 任务指令做成 human embodiment 数据。用你的固定桌面 AprilTag 和相机 VIO 把坐标变换到机器人基坐标，再报告定位误差与动作可行率。否则迁移失败时无法判断是底座表征不够还是位姿误差过大。

**最重要的结论**：扩大无本体 human 数据库之前，先问机器人底座的任务、本体和场景覆盖率有多大。论文不等于「只用人类 RGB 即能训练可部署动作策略」。
