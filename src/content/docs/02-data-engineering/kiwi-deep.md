# KIWI — Kinematic Interface for the Wild

论文：[arXiv:2609.22809](https://arxiv.org/abs/2609.22809)。

> **状态**：论文方法解析＋公开组件的等效复现路线，不把未核实公开的作者专属 SLAM 系统说成已经完整开源。

![KIWI 摄像机与共享地图系统](/Embodied-AI-Roadmap/diagrams/kiwi-system.svg)

## 1. 研究动机

UMI 腕部操作视角容易被手、夹爪、操作物遮挡；同一个相机既要拍清楚操作、又要定位环境，两者存在天然冲突。KIWI 使用每手一台 360° 相机的**前/后两镜头分工**：前镜头拍操作，后镜头朝向房间，尽量提供稳定静态环境特征来定位。共享地图帮助两手无需互相共视仍处在同一世界系。

## 2. 硬件、传感器和模态

| 模块 | 数量 | 原始数据 | 主要功能 |
| --- | --- | --- | --- |
| 可取双鱼眼原始流的 360° 相机 | 左右手各 1 | 前/后 RGB、时间戳 | 操作与定位视角互补 |
| 相机 IMU（前提是型号开放接口） | 各 1 | acc、gyro 或厂家运动元数据 | 离线惯性融合 |
| 快拆支架、相机工具外参 | 2 套 | 固定几何参数 | 筷式/平行夹爪/腕部/法兰可换装 |
| 夹爪开度传感（可选） | 按配置 | 开合位置 | 构造可解释动作标签 |
| 头戴相机（可选） | 1 | EGO 视频 | 第一人称环境语义 |
| 标定/独立精度测量 | 1 套 | 基准数据 | 验证定位误差而非只看轨迹顺滑 |

**绝不能假设**：只要是 360° 成品相机就一定能导出未拼接的双鱼眼、硬件时间戳和 IMU。选型前用真实样本文件核验三者。

## 3. 完整信息流

双鱼眼原始视频 → 分前/后镜头 → 各镜头鱼眼内参、相机相互外参标定 → 后镜头环境建图 → 前镜头特征与 IMU 补偿 → 左右相机在公共地图中定位 → 工具安装外参 → 双手末端 6DoF → 速度/重定位/有效性 QC → 动作训练数据。

设世界系左右工具位姿 T_WL、T_WR，则右手相对左手：

$$
T_{LR}=T_{WL}^{-1}T_{WR}.
$$

如果两个 SLAM 系统的地图尺度与坐标系不同，则公式形式虽合法，求得的右手相对变换却不具有正确物理意义。

## 4. 论文性能怎么正确引用？

论文对六段双手录像报告：前后视角融合后约 0.1% 查询帧未定位；仅用前视角做双手特征对齐约 24.8% 失败，在特定评测标记上定位误差位于 4.5 mm 范围内。**这些不是任何工厂的普适精度**，且定位成功率不等于对机器人控制可用的高精度动作标签比例。

## 5. 可操作的四阶段复现

| 阶段 | 操作 | 必须验收 |
| --- | --- | --- |
| A 硬件接口 | 两台 360 相机导出双鱼眼、时间、IMU | 相机模型/原始帧确实可读取 |
| B 单相机定位 | 后镜头静态环境 SLAM，前镜头作补充 | 单机 ATE/RPE 和失败区间 |
| C 公共地图 | 双机地图对齐、轨迹到公共世界系 | 已知双手相距验证、漂移 |
| D 抓取示范 | 工具外参、夹爪开度、episode 转换 | 标注真值语义、丢帧、成功率 |

实验先从光照和纹理稳定的房间开始，再测试反光金属、重复工位、动态人员、快速甩动、左右互不共视。**低纹理/动态工厂条件是重点风险**。

### 相对坐标自测代码

~~~python
import numpy as np
left=np.eye(4); right=np.eye(4)
right[:3,3]=[0.3,0,0]
relative=np.linalg.inv(left)@right
assert np.allclose(relative[:3,3],[.3,0,0])
~~~

此代码只验变换规则，**并没有复现作者的 360° SLAM**。

## 7. 和其他三种方案的选择

KIWI 主要针对“腕部遮挡造成 SLAM 定位缺失”；HiFi-UMI 更关注精准双手轨迹与同步；MonoEgo 借固定锚点提供尺度；Ego-OSCAR 重点是低成本头戴双目惯性数据。不能单纯用“定位率最高”选择训练数据生产方案，必须把动作标签可用率和闭环策略增益纳入决策。
