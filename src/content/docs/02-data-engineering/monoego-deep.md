# MonoEgo：Monocular Metric Egocentric Demonstration Capture

论文：[arXiv:2609.34512](https://arxiv.org/abs/2609.34512)。

> 这里区分**论文已说明的系统机制**和**基于 OpenCV/公开 SLAM 的替代实现**。没有作者完整工程与参数时，不应把替代算法称为同等精度的原版复现。

![MonoEgo 单目相机、标记、锚点、重建全流程](/Embodied-AI-Roadmap/diagrams/monoego-system.svg)

## 一、最主要贡献：尽量不用腕部电子设备

普通单目 SLAM 在没有尺度证据时不能唯一确定场景的真实米制尺度。MonoEgo 使用**单个 90 FPS 全局快门相机**观察操作场景、腕部已知几何的被动标记阵列和少量固定工位锚点；所有视觉观测天然使用同一个图像时钟。腕标记不需要自身电子供电，但需要视野可见性和精确尺寸。

## 二、硬件与数据

| 部件 | 类型 | 原始/直接获得 | 估计/派生 |
| --- | --- | --- | --- |
| 90 FPS 全局快门单目相机 | 唯一主动视觉设备 | RGB/时间戳 | 视觉相机世界系位姿 |
| 被动腕部 constellation | 两手固定几何标记阵列 | 图像角点 | 腕标记相机系位姿 |
| 稀疏工位 anchor | 尺寸/位置已知标记 | 图像角点与尺度证据 | 米制地图尺度和重定位 |
| 头戴/腕部安装件 | 刚体结构 | 工具外参标定 | 真实末端位姿转换 |
| 离线重建主机 | 计算模块 | 无新的原始传感模态 | MonoTag SLAM 和有效性数据 |

**不要虚构**：普通被动视觉标记不会直接测出夹爪开度、关节力矩或人手触觉；这些需额外传感器或独立估计。

## 三、算法详解：MonoTag SLAM

1. **标定**：相机畸变/内参、标记三维尺寸、相机与腕部工具的刚体外参。
2. **视觉前端**：提取 ORB 场景特征及标记四角，维护帧间关联。
3. **PnP 与 IPPE**：利用平面 marker 已知尺寸进行位姿估计，保留 IPPE 的候选解。
4. **几何判别**：平面标记易出现两组具有相近重投影误差的姿态解，必须结合运动连续性、地图约束和标记视角，拒绝没有支持证据的解。
5. **米制 Atlas**：用已验证工位锚点恢复/重锚定尺度；多地图合并需显式证据。
6. **回溯定位**：最终地图可能帮助定位此前遗漏的帧，但不能因此把所有未观测帧填成可信真值。
7. **导出数据**：camera_pose、left/right_wrist_pose、validity、map_id、scale_provenance、重定位标志和操作视频。

### 变换链不能搞错方向

定义 T_WC 为相机在世界系位姿，T_CM 为腕标记在相机系位姿，T_ME 为工具位姿在 marker 系下外参：

$$
T_{WE}=T_{WC}T_{CM}T_{ME}.
$$

每个 T 必须使用同一时刻的观测，坐标系统一且尺度可靠。最终位姿误差来自各环节累积，不能仅凭某单帧 PnP 小重投影误差断言工具轨迹精度高。

## 四、实际复现的最小程序

~~~bash
python -m pip install opencv-python numpy
~~~

~~~python
import cv2, numpy as np
obj=np.array([[-.02,-.02,0],[.02,-.02,0],
              [.02,.02,0],[-.02,.02,0]],np.float32)
img=np.array([[220,180],[300,178],[305,258],[218,260]],np.float32)
K=np.array([[500,0,256],[0,500,256],[0,0,1]],np.float64)
ok,rvecs,tvecs,errors=cv2.solvePnPGeneric(
    obj,img,K,np.zeros(5),flags=cv2.SOLVEPNP_IPPE)
print("候选数",len(rvecs),"重投影误差",errors)
~~~

这里是**合成角点验证 IPPE 双解机制**，不是 MonoTag SLAM 全量代码。真正完整替代实现还要实现帧间 ORB 跟踪、局部 BA、地图合并、尺度证据管理和数据有效性审计。

## 七、主要局限

论文并不保证持续看不到标记时还拥有严格真实位姿。低纹理、反光工位、快速运动、工件遮挡、错误锚点合并，都可能造成几何不确定性。建议先在静态工位验证，再决定是否扩展到大规模移动操作。
