# HiFi-UMI：从六路视觉到可训练双臂动作

论文：[arXiv:2607.25895](https://arxiv.org/abs/2607.25895)；公开数据：[HiFi-UMI-2K](https://huggingface.co/datasets/simple-world-lab/HiFi-UMI-2K)。

![HiFi-UMI 六路同步到机器人动作的全链路](/Embodied-AI-Roadmap/diagrams/hifi-umi-system.svg)

## 1. 为什么需要 HiFi-UMI？

传统腕部 UMI 拍得到操作视频，但轨迹可能漂移、丢失尺度，夹爪遮挡会影响视觉定位，两只手若在不同世界系 SLAM 下估计，相对运动可能失真；若动作与曝光时间不一致，同一帧与标签实际对应不同操作阶段。HiFi-UMI 的核心不是单纯“多装摄像头”，而是将**多视角覆盖、空间高精度、双手共参考和硬件时间同步**作为一个系统设计，争取让无本体演示数据直接支持后训练。

## 2. 硬件系统与传感器（注明测量/派生）

| 子系统 | 数量/构成 | 原始模态 | 派生数据 | 选型关键 |
| --- | --- | --- | --- | --- |
| 头戴双目 | 左右摄像机两路 | 双目 RGB | 深度/头部 6DoF | 同步、标定、视场 |
| 头部惯性 | 1 套 IMU | 加速度、角速度 | Stereo-inertial 位姿 | 时钟和噪声 |
| 左右腕部视觉 | 每手 2 路，共 4 路 | 四路操作 RGB | 双手定位/工具轨迹 | 遮挡、畸变、固定外参 |
| 左右夹爪 | 每手 1 套 | 开合状态（如装编码器） | 抓握事件/动作标签 | 开合标定、工具坐标 |
| 参考标记和结构件 | 随系统布置 | Marker 像素观测 | 双手共享世界系 | 几何尺寸和重投影 |
| 触发/时钟 | GPIO/记录端 | 曝光事件、时间戳 | 同步对齐 | 时钟漂移和漏触发 |

**六视角 = 头戴 2 + 腕部 4。** 文献中的组合视场不等于每个镜头都有相同超广角 FOV。不能把“估计出来的 6DoF”写成“IMU 直接输出绝对 6DoF”。

## 3. 输入→处理→输出架构

1. 相机和 IMU 原始采集：RGB(t)、acc(t)、gyro(t)、夹爪开合(t) 与硬件触发；
2. 各相机内参/畸变、刚性安装外参、相机与工具坐标系标定；
3. 头戴双目惯性 SLAM 获得公共参考轨迹与尺度；
4. 双腕视觉/标记观测结合共享参考，生成左右腕位姿和双手相对变换；
5. 根据事件时间戳统一采样时刻，对无效、漂移、遮挡帧保留 validity；
6. 构造机器人可学 Action Schema：坐标转换、动作相对化、旋转表示、归一化；
7. 视频和 Parquet 数据打包、质检、任务文本关联、训练与低速闭环验证。

### 为什么共参考重要？

若世界坐标中左右末端位姿分别为 T_WL、T_WR：

$$
T_{LR}=T_{WL}^{-1}T_{WR}.
$$

只有它们在**同一个尺度和世界原点**下，右手相对左手位姿才有可解释的物理意义。独立运行的两个 SLAM 世界系不能无条件直接相乘。

### 同步误差会带来多大偏差？

在局部近似恒速下：

$$
e\approx \|v\|\Delta t.
$$

速度 0.5 m/s，视频与位置错开 10 ms，可产生约 5 mm 位置偏差。定位精度和同步精度是不同指标，不能把微秒同步宣传成微米定位。

## 八、真正的数据接口契约：采集端必须落盘哪些内容

以下是建议的**通用 Canonical Schema**，不是论文官方定义。只有把每一列的物理语义锁死，下游模型才不至于“能训练却学错”。

| 字段 | 建议单位/格式 | 严格要求 |
| --- | --- | --- |
| episode_id | 字符串 / UUID | 一段任务不跨越多个不可解释的地图重置 |
| timestamp_ns | int64，统一单调时钟 | 说明时间原点，禁止混用 unix wall clock 与 MCU clock |
| rgb.* | 视频或压缩图帧 | 相机名、frame_id、曝光起点、有效性 |
| imu.acc | m/s² ×3 | 说明 IMU 坐标轴和重力方向 |
| imu.gyro | rad/s ×3 | 标定陀螺零偏，说明轴向 |
| pose.world_* | 4×4 / SE(3) | 指明 T_AB 的左右下标含义；明确位置单位米 |
| pose_valid | bool | 缺少可靠重建时必须 false |
| pose_source | 枚举 | 直接 marker、VIO、Atlas 回溯或插值 |
| gripper | m、rad 或归一化比例 | 绝不能无单位混用 |
| action | [H,D] | 明确绝对/增量、参考系、未来时刻和有效维度 |
| quality.* | 分项分数/事件 | 数据缺失、重投影、时间偏差、运动异常分别存储 |

### 坐标系的两条不变量

**不变量 A：**相同物理标记固定不动时，变换链求得的世界位姿应保持近似不变；模型不能通过人为平滑掩盖系统性的标定偏差。

**不变量 B：**如果坐标系链为世界 W→相机 C→工具 E，那么全部 T 的定义必须一致。以列向量惯例为例：

$$
T_{WE}=T_{WC}T_{CE}.
$$

对于动作增量，一种常见相对位姿定义为：

$$
\Delta T_t=T_{WE}(t)^{-1}T_{WE}(t+1).
$$

这属于**当前工具局部系**下的相对变换。若需求是世界系增量，应另作定义，二者不能混用。旋转差不能随意用欧拉角逐维相减代替 SE(3) 变换复合。

### 从原始轨迹生成训练样本

推荐先做“独立于训练网络的数据协议验收”：解码传感器→时间插值或选择最近曝光时刻→处理无效帧→统一位姿/工具外参→归一化 action→窗口化未来 H 步→构建观测/动作样本。

最小有效性门槛不只是“没有 NaN”：相机重定位后突然跳变、不同 SLAM 地图被无条件拼接、夹爪状态与视频错位，即使全部数字合法也不应进入真值监督。

## 九、质量验证脚本：时间、速度与异常检查

~~~python
import numpy as np

def verify_timestamps(ts_ns):
    t=np.asarray(ts_ns,dtype=np.int64)
    assert t.ndim==1 and len(t)>2
    dt=np.diff(t)/1e9
    assert np.all(dt>0), "时间戳重复或倒退"
    return {"median_dt_s":float(np.median(dt)),
            "p95_dt_s":float(np.percentile(dt,95)),
            "max_dt_s":float(dt.max())}

def velocity_from_position(positions, ts_ns):
    p=np.asarray(positions,dtype=float)
    assert p.ndim==2 and p.shape[1]==3
    dt=np.diff(np.asarray(ts_ns,dtype=np.int64))/1e9
    assert len(dt)==len(p)-1 and np.all(dt>0)
    return np.linalg.norm(np.diff(p,axis=0)/dt[:,None],axis=1)

t=np.arange(101,dtype=np.int64)*50_000_000
p=np.stack([np.arange(101)*0.01,np.zeros(101),np.zeros(101)],axis=1)
print(verify_timestamps(t))
print("speed m/s", np.median(velocity_from_position(p,t))) # 0.2
~~~

**这段脚本只做基础体检，不是 SLAM 或策略训练代码。** 使用时进一步补充姿态角速度、mask 对应、有效区间、数据格式和独立真值对照。超阈值是否一定是错误，要结合工况，不能把真实快速动作全部过滤掉。

## 专题深化：双手公共几何、精度和训练路径

![HiFi-UMI 专题分层技术图](/Embodied-AI-Roadmap/diagrams/hifi-umi-detail.svg)

### 1. 双目为何提供尺度、但不等于毫米精度？

对理想已校正双目，深度近似为：

$$
Z=\frac{fb}{d}.
$$

其中 f 是像素焦距、b 是相机基线（米）、d 是视差（像素）。假设 f=500、b=0.08、d=20，则 Z=2 m；这些数字用于手算，**不是论文实物规格**。对视差求导：

$$
\left|\frac{\partial Z}{\partial d}\right|=\frac{fb}{d^2}.
$$

随深度增加，视差减小，同样的像素误差往往带来更大的深度不确定性。双目惯性 SLAM 还需要 IMU 零偏、重力方向、双目外参和时间偏移标定。相机硬件同步不能替代这几项。

### 2. 共世界系才允许计算双手相对姿态

定义 T_WL、T_WR 为世界 W 中左右工具位姿，则：

$$
T_{LR}=T_{WL}^{-1}T_{WR}.
$$

如果左右两手分别使用独立、未注册的 SLAM 地图，上式的矩阵可以相乘，但结果没有可信的真实几何含义。工具相对相机外参应由刚性工装标定；即使视觉位姿准确，工具安装晃动也会让操作轨迹错误。

### 3. 时间戳失配对动作监督的伤害

局部恒速近似下：

$$
e_{\mathrm{time}}\approx\|v\|\Delta t.
$$

若工具速度 0.6 m/s，时间偏差 0.015 s，位置误差约 9 mm。必须分别报告曝光同步、轨迹定位、工具安装误差，不能把微秒同步直接理解成微米运动精度。

### 4. 如何建立可验证的数据训练闭环？

原始六路视频和惯性数据 → 相机/IMU 标定 → 世界系双手工具位姿 → 同步重采样 → 无效区间过滤 → 动作的绝对或相对定义 → 未来 H 步样本 → 数据标准化和训练 → 独立真实机器人闭环评测。

对于世界系工具位姿序列 T(t)，一种工具系相对动作定义：

$$
\Delta T_t=T(t)^{-1}T(t+\Delta t).
$$

如果训练骨干接受绝对下一个状态，就要在 Adapter 中明确定义如何转换；**不得把两种 Action Schema 混为同一个标签**。

### 5. 推荐的真实消融

保留其他配置不变，依次测试：去硬触发改软件对齐、取消共享双手世界系、减少每手一个辅助镜头、取消仿真回放 QC。每次记录双手相对位姿误差、有效标签率以及最终机器人任务成功率。论文结果只有在相应实验设置下成立，不能直接复制成自研设备验收值。

## 一条 Episode 的复现验收：读入、校时、几何、训练

**第一关：数据来源。** 固定 HiFi-UMI-2K 的下载版本和许可，抽取一条包含左右手状态、头戴与腕部相机视频的 episode。记录实际 Parquet 列、每路视频帧数、时间戳来源和数据单位。未知字段先列为待核实，禁止猜测为真值。

**第二关：时间与轨迹。** 在统一单调纳秒时间轴上计算 dt，要求严格单调；再将世界系工具位置对时间求差得到速度。轨迹在重定位处发生跳跃时应设无效段，不得把所有连续插值当作真实监督。

**第三关：工具坐标。** 显式标定左右腕相机到工具末端的固定外参，用已知静止工装检查变换链是否闭合。对于世界系位姿 T_Wt，若训练目标是工具局部系相邻位姿增量，采用：

$$
\Delta T_t=T_{Wt}^{-1}T_{W,t+1}.
$$

**第四关：动作和数据集。** 明确 Rot6D 转 SO(3) 的正交化过程、夹爪开合单位和范围、动作 Horizon、无效维度 Mask。不能把绝对 next-state 标签不经说明就替换成 Delta Action。

**第五关：模型实测。** 固定机器人本体、采样频率、动作空间、训练预算和测试任务，分别评估动作标签有效率、闭环任务成功率、接触失败、轨迹安全与推理延迟。只有这些结果具备完整日志，才能判断数据价值，不能以下载完成视为复现完成。


## 独立专项：按 HiFi-UMI 一步步做出最小复现

### 第一步：先确认数据契约，而不是立即训练

先在记录表中固定一条 episode 的全部相机名称、每路图像分辨率、帧时间戳、有效性，以及左/右工具 pose 与 gripper 的原始字段。每一个字段都记录**数据出处、单位、坐标系、原始/派生性质**。任何缺失字段不能用“应该有”代替实测。

### 第二步：验证从 rot6d 到 SE(3)

6D Rotation Representation 通常将两个三维向量正交化，恢复合法旋转矩阵。下方是可运行的 NumPy 教学实现，不能把它误认为官方数据读取器：

~~~python
import numpy as np

def rot6d_to_R(x):
    a=np.asarray(x[:3], dtype=np.float64)
    b=np.asarray(x[3:6], dtype=np.float64)
    assert np.linalg.norm(a)>1e-8
    x1=a/np.linalg.norm(a)
    b=b-x1*np.dot(x1,b)
    assert np.linalg.norm(b)>1e-8
    x2=b/np.linalg.norm(b)
    x3=np.cross(x1,x2)
    return np.stack([x1,x2,x3],axis=-1)

R=rot6d_to_R([1,0,0,0,1,0])
assert np.allclose(R.T@R, np.eye(3), atol=1e-7)
assert np.isclose(np.linalg.det(R),1.0)
print("R =",R)
~~~

旋转矩阵必须满足：

$$
R^\top R=I,\qquad \det R=1.
$$

原始 6D 向量出现退化或零长度时必须显式报错，不能让 NaN 悄悄进入 Action Label。

### 第三步：动作绝对值与局部增量不能混淆

设某帧末端世界系位姿为 $T_{WE,t}$。若采用工具**局部系相邻增量**，应计算：

$$
\Delta T_t=T_{WE,t}^{-1}T_{WE,t+1}.
$$

但如果训练模型要求基坐标系下的绝对末端目标，这个 $\Delta T$ 不能原样输入。先确定机器人 action adapter 的语义，再转换数据。训练、离线回放与部署三端必须保持一致。

### 第四步：建立最小可视化验收

把一条 episode 展示成四个同步视图：头戴 RGB、左手腕 RGB、右手腕 RGB、三维双手轨迹。用时间轴标红被 mask 的帧，同时绘制夹爪开合状态。你应该能用肉眼核查“接近杯子—夹紧—抬起—释放”等事件是否与动作曲线一致。

### 第五步：把动作训练拆成可判定的实验

第一组只用有效帧做模仿学习；第二组加入补插的低置信帧；第三组只改变动作坐标表达；第四组比较单手与双手相对表示。数据划分必须按**任务/场景/采集段**隔离，不能把同一条演示的相邻窗口泄漏到训练与验证两侧。

**交付判据**：提供数据 Schema、1 条完整 episode 的同步预览、重投影/时间偏差统计、动作空间单元测试、训练配置与日志。缺少其中任何一项都只能认为“教程完成”，而不是“论文已复现”。
