01｜先从一个任务理解

假设机器人收到指令：“把红色杯子放进托盘。” 摄像头看到杯子与托盘，机械臂当前关节和夹爪状态也已知。模型需要产生的不是一句话，而是后续多步连续控制量。

理解“要做什么”

红色杯子在哪里？哪个是托盘？当前任务需要抓起、移动还是放下？

视觉 + 语言上下文
决定“具体怎么动”

末端接近路径、夹爪什么时候闭合、未来一段动作如何连贯。

条件连续动作生成
抓住核心：π₀ 并不是 VLM 先生成一句计划，再调用一个完全独立的控制器。它让视觉语言侧与动作侧的 Token 在 Transformer 中交互，动作侧用 Flow Matching 建模连续动作块。

02｜整体架构：两类 Token，共同计算

图 1｜教学重绘，强调信息流；实际联合注意力发生在多层 Transformer 内，并非图中的单独后处理模块。依据原始论文与 openpi 的 Pi0/Gemma 实现。

图里最容易误解的是“两个专家”：它不是把输入送给路由器，让 Router 决定用哪个专家。这里是视觉语言侧和动作侧分别具有参数、共同参与注意力计算；动作端借助语言视觉上下文进行连续控制预测。

一定不要混淆：“Action Expert”不是独立完成机器人安全控制的真实控制器；最终动作还需要下游机器人控制接口。下图里“联合注意力”是为了教学直觉简化。

03｜Token 从哪里来？维度是什么？

首先将多相机图像变成视觉 token，语言变成文本 token；随后机器人状态投影成 state token，而带噪动作块的每个时间步经动作投影形成 action token。原始 π₀ 的时间嵌入与带噪动作嵌入融合后送入动作专家。

变量示例形状作用
相机图片[B,N,3,H_img,W_img]N 路相机，不同数据可不同
语言[B,L]语言 Token 序列
State[B,D_s]机器人 proprioception
Action Chunk[B,50,32]openpi 默认最大时间长度/维度
模型预测[B,50,32]动作空间中的速度场

举例：假设每个控制步的实际动作只有 7 维，模型的动作容器设为 32 维，那么必须在数据适配器中规定这 7 维对应什么、其它维度如何填充、如何归一化。32 维不等于机器人一定有 32 个关节。

两个数字不能混淆：预测未来 50 步动作（Action Horizon）和用 10 次积分得到动作（Flow Steps）是两个完全不同的维度。10 次积分每次更新的是整段 50 步动作。

04｜Attention Mask：谁能看见谁？

这是检验是否真正理解 π₀ 的关键。为方便理解，下图把大量 Token 简化为两个观察 token（P1、P2）和三个动作 token（A1～A3）。横轴是 Key，纵轴是 Query。

图 2｜简化的可见性矩阵。真实 token 数量更多，需同时考虑 padding mask；根据 openpi 的 make_attn_mask 与 mask_ar 分块规则重绘。

思考：为什么要阻止 Prefix 读取带噪动作？因为一次 Flow 采样需要多次改变动作噪声，如果 Prefix 依赖动作，它也必须随着采样步重算，难以缓存固定的图像和语言表示。

代码读法：打开 pi0.py，先定位 make_attn_mask，检查 mask_ar 的累计方式，再看 prefix/suffix 构建时设定了什么分块边界。

05｜训练到底让模型预测什么？

网络的最终输出不是“杯子的位置”，也不是“下一个单独动作”，而是整段带噪动作对应的速度场。理解这个设计，需要区分训练时的直接监督与推理时的多步积分。

图 3｜训练和推理的不同计算路径。简图省略了相机/语言/state 条件，它们始终参与速度预测。

以 openpi 的时间方向为例：xₜ=(1−t)A+tε，监督速度为 uₜ=ε−A。训练网络拟合 vθ(xₜ,t,观测)，推理从 t=1 的噪声出发，沿负时间方向更新，最后得到动作块。

别把这个 Flow 理解成图像光流。这里的“流”发生在机器人动作向量空间；它表示动作样本怎样沿连续路径从噪声变成目标分布。下一章会从二维几何例子推导公式与数值积分。

# 教学伪代码：解释数据流，不等于官方实现
obs = encode_images_and_text(images, instruction)
state_token = project(state)
noisy = (1 - t) * actions + t * gaussian_noise
action_tokens = project(noisy, t)
velocity = joint_transformer(obs, state_token, action_tokens)
loss = mean_square(velocity, gaussian_noise - actions)

在面向训练的真实代码中，还必须检查哪些参数设为 trainable、动作有效维度的 mask、数据归一化和机器人适配器。不能直接从图里推断“VLM 一定冻结”或“所有机器人都使用相同动作语义”。
