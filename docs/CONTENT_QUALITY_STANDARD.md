# 技术教材编写与验收规范

## 每篇必须满足的八项要求

1. 为什么提出该技术：真实失败案例和替代方法不足。
2. 输入输出完整：张量形状、物理单位、坐标系与每个处理模块。
3. 内部结构清楚：网络参数、损失函数、采样器、执行接口分开。
4. 数学推导完整：定义变量、条件假设、每一步公式与手算样例。
5. 代码可运行：标注教学代码与官方源码差别，附预期 shape/输出。
6. 训练推理分离：谁提供真值、谁接收梯度、推理时哪些变量可用。
7. 方案对比明确：优点、代价、失败条件、适用场景。
8. 学习闭环：练习、参考答案、调试路径、和 π₀ 等原始论文对应。

## 每张模型架构图必须审查

- 所有箭头标记信息流方向，不得把训练标签画作推理输入。
- 输入、输出、每个主要中间张量写出语义和维度。
- Q/K/V、Mask、Transformer 层、损失、积分、机器人控制器区分层级。
- 图色彩对比和字体需适配桌面/手机。
- 标明教学简化、省略部分以及对应原始来源。
- 图的可访问性和 SVG 文件完整性不代表逻辑正确，必须人工逐箭头复核。

## 上线前的最小检查

1. 检查 Markdown 公式分隔符和 LaTeX 语法。
2. 实际生成 Astro HTML 并检测 KaTeX 输出，而非只解析 LaTeX 源码。
3. 核查图片资源路径、SVG viewBox、文字溢出。
4. 浏览器桌面与手机截图抽检典型页面。
5. 若页面尚未实测，明确标记未验收，不能宣称完工。
