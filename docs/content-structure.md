# 内容分类与论文系列组织规范

本项目沿用六大技术领域作为一级目录。**技术领域解决文章放在哪里，论文系列解决一组有关联的工作怎么连续阅读。** 两者不是同一级分类。

## 一级领域

1. **具身基础模型**：模仿学习、强化学习、VLA、世界模型。
2. **具身数据工程**：EGO、UMI、手套、采集、清洗和训练格式。
3. **感知与重建**：SLAM/VIO、深度、手部姿态、手物交互。
4. **Human-to-Robot**：动作转换、跨本体表征和任务迁移。
5. **控制与执行**：运动规划、双臂协调、力控和任务编排。
6. **仿真与评测**：MuJoCo、Isaac Sim、基准测试与真机验证。

## 具身基础模型：按研究方向，再按论文家族

### VLA
- **Physical Intelligence π 家族**：π₀、π₀-FAST、π₀.₅ 等。见 [π 系列目录](papers/pi-series/README.md)。
- **RDT 家族**：同一研究线的连续工作（具体版本逐篇核验后收录）。
- **NVIDIA GR00T 家族**：同一模型家族的技术报告、版本及开源实现（逐篇核验）。
- 其他 VLA 家族在确有连续论文/模型演进时建立，不能为单篇论文硬建一个系列。

### 世界模型
- **Dyna 家族**：围绕相同研究线的版本与技术演进组织，逐篇确认同源关系。
- **Gen 系列**：仅在确认具体模型、团队和版本关系后归档，不把名称中含「Gen」的不同项目误合并。
- 其他世界模型按各自研究团队及模型家族整理。

### 模仿学习 / 强化学习
先以方法和知识点为入口（BC、ACT、Diffusion Policy、PPO 等）；只有同一研究线出现明确后续工作时，才建立论文家族。

## 单篇论文与系列的关系

- 每篇论文只有**一个正文地址**。
- 系列目录按演进关系列论文：提出什么 → 改了什么 → 为什么改 → 实验怎么验证。
- 技术文章还可被学习路线、跨论文比较、工程实践引用，但不重复拷贝正文。
- 不同团队讨论同一个问题属于**技术专题**，不叫论文家族。

## 深度解读统一要求

每篇深入讲解依次包括：问题和基线、核心设计、输入输出与张量、训练目标与梯度、推理与部署、实验消融、局限、源码定位、最小验证动作。后续版本必须重点对比上一版本变更，避免重复基础知识。

**发布原则：** 没有原始来源不添加事实性指标；未实际运行的代码不标为“已复现”；厂商声称和作者实验不能写成独立验证。
